# API Reference

Interactive OpenAPI/Swagger docs are auto-generated by FastAPI at `/docs`
(Swagger UI) and `/redoc` when the app is running; this page is the narrative
contract plus sample client usage. See [ARCHITECTURE.md](ARCHITECTURE.md) for
how this fits into the overall system.

## Auth

Every `/api/v1/*` route requires an `X-API-Key` header. Keys are configured
via `Settings.api_keys` (comma-separated), one per HR-system integration so
usage can be attributed and revoked individually.

```
X-API-Key: dev-key
```

Missing or unrecognized keys get `401 Unauthorized`.

## Versioning

The API is path-versioned: `/api/v1/...`. Breaking changes ship as `/api/v2/...`
alongside the previous version rather than mutating `v1` in place; additive,
backwards-compatible fields don't require a version bump.

## Rate limiting

Each API key is limited to `Settings.rate_limit_per_minute` requests/minute
(default 60), fixed-window. Exceeding it returns `429 Too Many Requests` with
`Retry-After: 60`. This is an in-memory, per-process limiter — fine for a
single API instance; move to a Redis-backed limiter before running multiple
instances behind a load balancer (see TASKS.md P3).

## Endpoints

### `POST /api/v1/screenings` — score one resume, synchronously

Target latency: p95 < 2s (docs/SCOPE.md). Resume content is sent inline as
base64 — no separate upload step.

Request:
```json
{
  "job_description": "Senior backend engineer. Requires Python, AWS, and 5+ years experience.",
  "resume": {
    "candidate_id": "cand-123",
    "filename": "jane-doe.pdf",
    "content_base64": "<base64-encoded file bytes>"
  }
}
```

Response `200`:
```json
{
  "candidate_id": "cand-123",
  "score": 72.5,
  "matched_skills": ["python", "aws"],
  "missing_skills": ["kubernetes"],
  "explanation": [
    {"factor": "semantic_similarity", "detail": "embedding cosine similarity between resume and JD: 0.81", "weight": 0.6},
    {"factor": "skill_coverage", "detail": "2/3 required skills present in resume", "weight": 0.4}
  ],
  "model_version": "skill-coverage-v1+semantic-all-mpnet-base-v2"
}
```

If the semantic embedding model isn't installed/available (see the optional
`ml` extra in `pyproject.toml`), scoring degrades to skill-coverage-only —
`model_version` reports `skill-coverage-v1` so callers can tell which mode
produced a given score. This keeps the endpoint available even before the
embedding model is provisioned, at reduced ranking quality.

Accepted file types: `.pdf`, `.docx`, `.txt`, max 5MB decoded.

### `POST /api/v1/screenings/batch` — submit a batch for async screening

Up to 500 resumes per batch (docs/SCOPE.md target). Returns immediately with
a job id; screening runs on the task queue so the caller isn't blocked on
model inference.

Request:
```json
{
  "job_description": "Senior backend engineer...",
  "resumes": [
    {"candidate_id": "cand-1", "filename": "a.pdf", "content_base64": "..."},
    {"candidate_id": "cand-2", "filename": "b.docx", "content_base64": "..."}
  ],
  "webhook_url": "https://ats.example.com/hooks/resume-ai"
}
```

Response `202`:
```json
{"job_id": "6f1e...", "status": "queued", "submitted_count": 2}
```

### `GET /api/v1/screenings/batch/{job_id}` — poll batch status/results

```json
{
  "job_id": "6f1e...",
  "status": "processing",
  "total": 2,
  "completed_count": 1
}
```

Once finished, `status` becomes `"completed"` and `results` is populated with
one `ScoreResult` per resume (same shape as the sync endpoint's response).
`status: "failed"` includes an `error` string.

### Webhook callback

If `webhook_url` was set on the batch request, the API POSTs this payload to
it once when the job finishes (2s/4s/... backoff, 3 attempts; a subscriber
being unreachable does not fail the underlying screening job):

```json
{
  "job_id": "6f1e...",
  "status": "completed",
  "results": [ /* ScoreResult[] */ ]
}
```

## HR/ATS integration adapters (`integrations/`)

These are mapping functions, not network calls — they translate an external
payload shape into the `resumes` list the batch endpoint expects
(`{candidate_id, filename, content_base64}`); the caller still POSTs to
`/api/v1/screenings/batch`.

- `integrations.csv_import.parse_bulk_csv(csv_bytes)` — bulk import from a
  CSV export. Supports either `candidate_id,filename,content_base64` columns
  (pre-encoded files) or `candidate_id,resume_text` (plain text, wrapped into
  a synthetic `.txt` file).
- `integrations.ats.greenhouse.from_greenhouse_candidate(payload)` — maps a
  Greenhouse Harvest API candidate object (with an inline-fetched resume
  attachment) to our format.
- `integrations.ats.workday.from_workday_candidate(payload)` — generic
  mapping for Workday recruiting candidate payloads; Workday's schema is
  tenant-customized, so field lookups may need adjusting per tenant.
- `integrations.webhooks.deliver_webhook(url, payload)` — used internally by
  the batch task; retried POST with backoff, never raises.

## Sample client usage

**curl** — sync screening:
```bash
curl -X POST http://localhost:8000/api/v1/screenings \
  -H "X-API-Key: dev-key" \
  -H "Content-Type: application/json" \
  -d '{
        "job_description": "Backend engineer, Python + AWS, 5+ years",
        "resume": {
          "candidate_id": "cand-123",
          "filename": "resume.txt",
          "content_base64": "'"$(base64 < resume.txt)"'"
        }
      }'
```

**Python (`requests`)** — batch submit + poll:
```python
import base64
import time

import requests

API = "http://localhost:8000/api/v1"
HEADERS = {"X-API-Key": "dev-key"}


def encode(path: str) -> str:
    with open(path, "rb") as f:
        return base64.b64encode(f.read()).decode("ascii")


resp = requests.post(
    f"{API}/screenings/batch",
    headers=HEADERS,
    json={
        "job_description": "Backend engineer, Python + AWS, 5+ years",
        "resumes": [
            {"candidate_id": "cand-1", "filename": "a.pdf", "content_base64": encode("a.pdf")},
            {"candidate_id": "cand-2", "filename": "b.docx", "content_base64": encode("b.docx")},
        ],
    },
)
job_id = resp.json()["job_id"]

while True:
    status = requests.get(f"{API}/screenings/batch/{job_id}", headers=HEADERS).json()
    if status["status"] in ("completed", "failed"):
        break
    time.sleep(2)

print(status["results"])
```
